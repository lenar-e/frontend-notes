# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A bilingual (English default, Russian under `/ru/`) Docusaurus site of frontend interview tasks. Each task is TypeScript code + Vitest tests + an MDX page, and React tasks also get a live demo. Deployed to GitHub Pages from `main` by `.github/workflows/ci.yml` after all checks pass.

## Commands

Package manager is **Yarn** (classic, `yarn.lock`); Node version is in `.nvmrc`.

```bash
yarn verify                 # lint + format:check + typecheck + test — same as CI (CI also runs yarn build)
yarn test                   # all tests, including type tests (*.test-d.ts)
yarn test:watch
yarn vitest run notes/javascript/functions/debounce.test.ts   # single file
yarn vitest run -t "debounce"                                  # by test name
yarn vitest run --project dom                                  # only the jsdom project (or: node)
yarn typecheck              # tsc over the whole repo (one root tsconfig)
yarn lint / yarn lint:fix
yarn format / yarn format:check
yarn start                  # en site :3000, ru site :3001, demo :5173 (args: site | ru | demo)
yarn build                  # site (both locales) + demo into website/build/
yarn serve                  # serve the build — local search only works here
yarn new <section>/<category> <name> [--ru]   # scaffold a task
yarn write-translations     # pull new category/UI keys into website/i18n/ru JSON files
```

## Architecture

**`notes/` is content, `website/` is presentation.** All task code, tests and pages live in `notes/<section>/<category>/`, with the page always next to its code. `website/` holds the Docusaurus site, the Vite demo app and scripts.

- **Sections** are defined once in `website/src/data/sections.ts`. Each entry becomes a separate `@docusaurus/plugin-content-docs` instance (`id` = folder in `notes/` = URL base), plus navbar/footer/home page entries. Sidebars are autogenerated from folders; `_category_.json` sets labels/order. `website/scripts/new.mjs` has its own hardcoded `SECTIONS` list — keep it in sync when adding a section.
- **Pages show real code via raw-loader**: `import solution from '!!raw-loader!./debounce.ts'` then `<CodeFiles files={{ 'debounce.ts': solution }} />`. Never paste code into MDX — the page must show the file the tests run against.
- **Global MDX components** (no import needed, registered in `website/src/theme/MDXComponents.tsx`): `CodeFiles`, `LiveDemo`, `HtmlPreview` (HTML+CSS in an iframe, used by CSS section), `Tabs`, `TabItem`.
- **React demos**: any `notes/react/**/*.demo.tsx` (default export) is auto-registered in the demo app via `import.meta.glob` in `website/demo/registry.ts`. Demo id = kebab-case of the file name (`StarRating.demo.tsx` → `star-rating`), and the MDX page uses `<LiveDemo id="star-rating"><StarRatingDemo /></LiveDemo>` to embed it and link to the app. `toKebabCase` is duplicated in `registry.ts` and `new.mjs` and must stay identical.
- **URLs/ports** live in `website/site.config.ts`. In dev each locale runs its own Docusaurus server (the ru one uses `DOCUSAURUS_GENERATED_FILES_DIR_NAME=.docusaurus-ru`), and `docusaurus.config.ts` sets per-locale dev URLs so the language switcher works.
- `onBrokenLinks` and `onBrokenMarkdownLinks` are `throw` — broken links fail the build.

### Tests (`vitest.config.mts`)

Two Vitest projects chosen by path:
- `node`: `notes/{javascript,typescript,computer-science}/**/*.test.ts`, plus typecheck of `notes/typescript/**/*.test-d.ts` (TypeScript tasks are tested with `expectTypeOf`).
- `dom` (jsdom, `vitest.setup.ts` adds jest-dom matchers): `notes/{browser,react}/**/*.test.{ts,tsx}` and `notes/computer-science/security/**`.

A test file outside these globs won't run.

### i18n

- English sources are in `notes/`; Russian page translations go in `website/i18n/ru/docusaurus-plugin-content-docs-<section>/current/<same path>`. Category labels → `.../current.json`; navbar/footer → `docusaurus-theme-classic/*.json`; UI strings from `<Translate>` → `website/i18n/ru/code.json`.
- The site falls back to English for untranslated pages, but in this repo every page is written in both languages (see Rules). Code, comments and tests are English-only and shared.
- Translated pages can't use relative imports — they import via the `@notes` alias: `'!!raw-loader!@notes/javascript/functions/debounce.ts'`.

## Conventions

- Use `yarn new` to create tasks; it picks the template by section/name (React `PascalCase` → component folder with CSS module/test/demo, `use*` → hook, `typescript` → type + `*.test-d.ts`, `*/theory` and security non-`practice` → note, `system-design/cases` → RADIO template with Mermaid, `css` → `HtmlPreview` page) and creates missing `_category_.json`.
- Task pages follow the structure: Problem → (LiveDemo) → Solution → Explanation → Follow-up questions in `<details>`.
- **MDX is in `.prettierignore`** (Prettier breaks MDX 3 template literals) — format MDX by hand.

## Rules

- **Tests are mandatory.** Every task with code ships with tests: `*.test.ts(x)` for runtime code, `*.test-d.ts` for types. They go in a folder the Vitest globs above cover. Replace the `it.todo` placeholders from `yarn new` with real cases, including edge cases. Before finishing, run `yarn verify`.
- **Always write both languages.** Create pages with `yarn new … --ru` and write the English page (`notes/`) and its Russian translation (`website/i18n/ru/...`) in the same change. When a page's content changes, update its translation too. New UI strings (`<Translate>`) need entries in `website/i18n/ru/code.json`.
- **Keep navigation in sync in the same change:**
  - New task → mark it ✅ with a link in the `README.md` task list (the task list lives only there, `README.ru.md` links to it).
  - New category → `_category_.json` with label/position, then `yarn write-translations` and fill in the Russian label in `.../current.json`.
  - New section → `website/src/data/sections.ts`, the `SECTIONS` list in `website/scripts/new.mjs`, the `index.md` page of the section (plus its Russian version), the section lists in both `README.md` and `README.ru.md`, and the Russian labels in `navbar.json`, `footer.json` and `code.json` (via `yarn write-translations`).
  - A React demo → check that `<LiveDemo id>` matches the kebab-case demo file name. If you add a new folder under `notes/react/`, also add it to `GROUP_LABELS` in `website/demo/registry.ts`.
