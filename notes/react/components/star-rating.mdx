## Problem

Build a rating component with N stars:

- on hover, the stars up to the cursor light up;
- a click selects a value;
- there is a read-only mode;
- the component works with a keyboard and a screen reader.

## Explanation

- **Controlled component:** the parent owns the value (`value` + `onChange`); inside there is only the temporary `hovered` state.
- **Semantics:** picking one value out of several is a radio group, hence `role="radiogroup"` and `role="radio"` with `aria-checked`. A screen reader announces "3 of 5, selected".
- **Roving tabindex:** only the selected star has `tabIndex={0}`, the rest have `-1`. Tab enters the group in one step, and arrows change the selection — just like native `<input type="radio">`.
- **Buttons, not `<span>`:** focus, Enter and Space work out of the box.

## Follow-up questions

<details>
<summary>How do you support half stars?</summary>

Draw each star in two layers: a gray background and a yellow fill with `width: 50%` and `overflow: hidden`. Compute the hovered value from `event.nativeEvent.offsetX` relative to the star width, and make the keyboard step 0.5.

</details>

<details>
<summary>Why not native input type="radio"?</summary>

That works too — and is even more robust for accessibility: visually hide the inputs and make the stars `<label>`s. Then arrows and the `name` group work without JS. Custom buttons give more control over behavior, but you have to write all the semantics yourself.

</details>
