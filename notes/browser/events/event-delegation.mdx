## Problem

Write a `delegate(root, eventType, selector, handler)` function. It attaches **one** handler to `root` and calls `handler` for events coming from elements that match `selector` — including elements added later.

```ts
const unsubscribe = delegate(list, 'click', '.item', (event, item) => {
  console.log('Clicked', item.dataset.id);
});
```

## Explanation

- Most events **bubble**: a click on a `<span>` inside an `<li>` reaches the `<ul>`, and a handler on the `<ul>` sees it.
- `event.target` is the deepest element that was clicked. `closest(selector)` walks up from it and finds the element we need.
- `root.contains(target)` filters out matches above `root`: `closest` doesn't know where the container ends.
- Why bother: fewer handlers (memory), and no need to re-subscribe when elements are added — handy for lists and tables.

## Follow-up questions

<details>
<summary>Which events don't bubble, and what do you do about them?</summary>

`focus`, `blur`, `mouseenter`, `mouseleave`, `load`, `scroll` (on elements). Focus has bubbling counterparts: `focusin`/`focusout`. Another option is to listen in the capture phase: `addEventListener(type, listener, { capture: true })`.

</details>

<details>
<summary>What is the difference between event.target and event.currentTarget?</summary>

`target` is the element where the event happened. `currentTarget` is the element whose handler is running right now. With delegation, `currentTarget` is `root`.

</details>
