## Problem

Write a `debounce(fn, delay)` function. It returns a wrapper that postpones calling `fn` until `delay` ms have passed since the **last** call of the wrapper.

```js
const log = debounce(console.log, 300);

log('a');
log('b');
log('c');
// after 300 ms the console shows: 'c'
```

A typical use case is search-as-you-type: the request is sent only once the user stops typing.

## Explanation

- The timer id lives in a closure. Every call of the wrapper clears the old timer and sets a new one — so `fn` fires only after a pause.
- The wrapper is a regular `function`, not an arrow: this way it receives the `this` of the calling object. The timer callback is an arrow, so it takes `this` from the wrapper.
- The arguments also come from the last call — they are captured in the new timer's closure.
- `cancel()` is needed, for example, so a pending request is not sent after a component unmounts.

**Complexity:** O(1) per call.

## Follow-up questions

<details>
<summary>How is debounce different from throttle?</summary>

`debounce` waits for a pause and calls the function once after a burst of calls. `throttle` calls the function at most once per `delay` ms — including during a continuous burst (scroll, resize).

</details>

<details>
<summary>How do you add a leading option — a call at the start of a burst?</summary>

If there is no timer (`timerId === undefined`), call `fn` right away. Then, as usual, set a timer that only resets `timerId`. The first call of a burst fires instantly, the rest are ignored until the pause.

</details>

<details>
<summary>How do you return the result of fn?</summary>

Not synchronously: when the wrapper is called, `fn` has not run yet. You can return a promise that resolves with the result once the delayed call happens.

</details>
