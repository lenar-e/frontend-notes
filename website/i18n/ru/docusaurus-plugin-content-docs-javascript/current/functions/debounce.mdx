## Условие

Напишите функцию `debounce(fn, delay)`. Она возвращает обёртку, которая откладывает вызов `fn`, пока с момента **последнего** вызова обёртки не пройдёт `delay` мс.

```js
const log = debounce(console.log, 300);

log('a');
log('b');
log('c');
// через 300 мс в консоли: 'c'
```

Типичный пример — поиск по мере ввода: запрос уходит, только когда пользователь перестал печатать.

## Разбор

- Id таймера живёт в замыкании. Каждый вызов обёртки сбрасывает старый таймер и ставит новый — поэтому `fn` сработает только после паузы.
- Обёртка объявлена через `function`, а не стрелкой: так она получает `this` вызывающего объекта. Колбэк таймера — стрелка, поэтому берёт `this` из обёртки.
- Аргументы тоже берутся из последнего вызова — они попадают в замыкание нового таймера.
- `cancel()` нужен, например, чтобы отложенный запрос не ушёл после размонтирования компонента.

**Сложность:** O(1) на каждый вызов.

## Follow-up вопросы

<details>
<summary>Чем debounce отличается от throttle?</summary>

`debounce` ждёт паузы и вызывает функцию один раз после серии вызовов. `throttle` вызывает функцию не чаще одного раза за `delay` мс — в том числе во время непрерывной серии (скролл, resize).

</details>

<details>
<summary>Как добавить опцию leading — вызов в начале серии?</summary>

Если таймера нет (`timerId === undefined`), вызвать `fn` сразу. Затем, как обычно, ставить таймер, который только обнуляет `timerId`. Так первый вызов серии сработает мгновенно, а остальные будут проигнорированы до паузы.

</details>

<details>
<summary>Как вернуть результат fn?</summary>

Синхронно — никак: в момент вызова обёртки `fn` ещё не выполнилась. Можно возвращать промис, который резолвится результатом, когда отложенный вызов произойдёт.

</details>
