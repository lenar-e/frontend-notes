## Условие

Напишите функцию `promiseAll(values)`, которая работает как `Promise.all`. Она принимает итерируемый объект с промисами (или обычными значениями) и возвращает промис, который:

- резолвится массивом результатов **в исходном порядке**, когда зарезолвились все значения;
- реджектится с причиной **первого** отказа, не дожидаясь остальных.

```js
const sleep = (ms, value) => new Promise((r) => setTimeout(() => r(value), ms));

await promiseAll([sleep(300, 'a'), sleep(100, 'b'), 'c']);
// ['a', 'b', 'c'] — через 300 мс

await promiseAll([sleep(300, 'a'), Promise.reject(new Error('oops'))]);
// Error: oops — сразу
```

## Разбор

- Результаты записываются по индексу — `results[index] = value`, а не `push`. Промисы резолвятся в любом порядке, но массив сохраняет порядок входных данных.
- Счётчик `pending` считает, сколько значений ещё не готово. Опираться на `results.length` нельзя: если первым записать `results[2]`, длина уже станет 3.
- `Promise.resolve(item)` превращает обычные значения и thenable-объекты в настоящие промисы, и все они идут по одному пути.
- `reject` передаётся прямо в `then`. Промис завершается только один раз, поэтому следующие отказы и резолвы просто игнорируются — это и есть быстрый отказ (fail-fast).
- Для пустого входа счётчик никогда не уменьшится, поэтому промис сразу резолвится `[]`.
- `Array.from(values)` вызывается внутри executor: если итерируемый объект бросит исключение, оно превратится в реджект, а не в синхронную ошибку.

**Сложность:** O(n) по времени и памяти.

## Дополнительные вопросы

<details>
<summary>Отменяются ли остальные промисы, когда один реджектится?</summary>

Нет. У промисов нет отмены: оставшаяся работа продолжается, просто её результаты игнорируются. Чтобы действительно остановить запросы, передайте им общий сигнал `AbortController` и вызовите `abort()` в `catch`.

</details>

<details>
<summary>Чем Promise.all отличается от allSettled, race и any?</summary>

- `allSettled` никогда не реджектится — ждёт всех и возвращает `{ status, value | reason }` для каждого элемента.
- `race` завершается вместе с первым завершившимся промисом — неважно, успешно или нет.
- `any` резолвится первым успешным промисом и реджектится с `AggregateError`, только если отказали все.

</details>

<details>
<summary>Запускает ли Promise.all промисы параллельно?</summary>

Он ничего не запускает: промис — это результат уже начавшейся работы. К моменту, когда `Promise.all` получает массив, все запросы уже отправлены. Он только ждёт их. Чтобы ограничить параллельность, передавайте функции, создающие промисы, и запускайте их сами — это пул промисов.

</details>

<details>
<summary>Как типизировать, чтобы кортеж сохранял типы элементов?</summary>

Через mapped type по кортежу: `{ -readonly [K in keyof T]: Awaited<T[K]> }`. Ограничение `T extends readonly unknown[] | []` заставляет TypeScript вывести `[number, string]`, а не `(number | string)[]`. Так `Promise.all` объявлен в `lib.es2015.promise.d.ts`.

</details>
